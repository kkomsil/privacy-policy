# archive — 이전 버전 처리방침 보관소

처리방침이 개정되면 **직전 버전을 이 폴더에 동결**해 둡니다.
현행본(`index.html`)의 개정 이력 표에서 이전 버전 번호를 누르면 이 파일로 연결됩니다.

```
privacy-policy/
├─ CNAME
├─ index.html          ← 현행본
└─ archive/
   ├─ v1.0.html        ← 동결본 (수정 금지)
   └─ v1.1.html
```

## 왜 두는가

처리방침 제16조 ③ — "이전 버전의 처리방침은 제14조의 연락처로 요청하시면 제공해 드립니다."

파일을 남겨두면 정보주체가 요청할 필요 없이 바로 확인할 수 있어, 이 약속을 자동으로 이행하게 됩니다.
개인정보보호위원회의 처리방침 작성지침도 이전 버전 확인 수단을 두도록 권장합니다.

## 개정 절차

1. **동결** — 현재 `index.html` 을 `archive/<직전버전>.html` 로 복사

   ```bash
   cp index.html archive/v1.0.html
   ```

2. **등록** — `build_privacy_bilingual.py` 의 `VERSIONS` 리스트 맨 뒤에 새 항목 추가

   ```python
   {
       "v": "v1.1",
       "pub_ko": "2026년 10월 1일", "eff_ko": "2026년 10월 8일",
       "pub_en": "1 October 2026",  "eff_en": "8 October 2026",
       "note_ko": "제7조 수탁사 변경",
       "note_en": "Article 7 sub-processor updated",
   },
   ```

   > **`pub` 은 `eff` 보다 최소 7일 앞서야 합니다.**
   > 제16조 ②에서 "변경 시 시행 7일 전부터 고지"를 약속했기 때문입니다.
   > 정보주체의 권리에 중대한 변경이면 30일입니다.
   > 최초 제정(v1.0)에는 적용되지 않았지만, 이후 개정부터는 적용됩니다.

3. **본문 수정** — 원본 docx를 고치고 블록을 다시 추출, 영문은 `blocks_en.py` 수정

4. **빌드** — `python3 build_privacy_bilingual.py`
   표지 날짜·버전, 개정 이력 표, 이전 버전 링크가 자동 갱신됩니다.

5. **커밋** — 무엇을 왜 바꿨는지 커밋 메시지에 한 줄

6. **외부 타임스탬프** — <https://web.archive.org> 에 현행본 저장
   커밋 이력과 달리 본인이 손댈 수 없는 제3자 기록이라, 분쟁 시 게시 시점 입증에 쓰입니다.

## 지켜야 할 것

- **동결본은 절대 수정하지 않습니다.** 오탈자를 발견해도 그대로 둡니다. 그 시점의 사실을 보존하는 것이 목적입니다.
- **`git push --force` 금지.** 커밋 이력을 덮어쓰면 기록의 신뢰성이 사라집니다.
- **저장소는 Public 유지.** 이력이 외부에서 확인 가능해야 증거로 의미가 있습니다.
